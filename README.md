# gitops-demo-app

Приложение GitOps-системы: крошечный веб-сервис плюс CI, который собирает
образ и обновляет тег в конфигурационном репозитории. В кластер напрямую
этот репозиторий не деплоит, деплоем занимается ArgoCD (модель pull).

Парный репозиторий с конфигурацией и описанием всей системы:
[gitops-demo-config](https://github.com/wwwplotnikov/gitops-demo-config).

## Приложение

Сервис на стандартной библиотеке Python, без внешних зависимостей.

| Эндпоинт | Поведение |
| -------- | --------- |
| `/` | отдаёт имя и версию; версия = тег образа = commit SHA |
| `/healthz` | всегда 200, для liveness-пробы |

Версия берётся из переменной окружения `APP_VERSION`, которую проставляет
Helm при деплое. Это позволяет видеть, какой именно коммит крутится в кластере.

## CI

При пуше в `main` GitHub Actions:

1. собирает образ, тег = commit SHA;
2. пушит образ в GHCR;
3. коммитит новый тег в репозиторий `gitops-demo-config`.

Третий шаг замыкает GitOps: после него ArgoCD видит изменение в config-репо
и сам выкатывает новую версию в кластер. CI доступа в кластер не имеет.

## Структура

```
gitops-demo-app/
├── app/
│   └── main.py              веб-сервис
├── Dockerfile              slim-база, non-root (UID 10001)
└── .github/workflows/
    └── ci.yml              build, push в GHCR, обновление config-репо
```

## Запуск локально

```
docker build -t gitops-demo-app:dev .
docker run --rm -p 8000:8000 -e APP_VERSION=dev gitops-demo-app:dev
curl localhost:8000/
```

## Ключевые решения

| Решение | Причина |
| ------- | ------- |
| non-root пользователь в образе | ограничение ущерба при компрометации контейнера |
| тег образа = commit SHA | под репортит свой коммит, полная трассируемость |
| CI пишет тег в config-репо, а не деплоит сам | pull-модель: у CI нет доступа в кластер, деплой делает ArgoCD |
| отдельный PAT для записи в config-репо | least privilege: встроенный токен имеет права только на свой репозиторий |
